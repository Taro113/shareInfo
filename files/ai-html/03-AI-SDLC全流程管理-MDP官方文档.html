1、背景

研发交付并非孤立的编码过程，而是研发、产品、QA 深度协同的全链路体系，从需求评审、技术方案设计、AI Coding，到集成/UI 测试与运维，每个阶段环环相扣。

AI-SDLC（AI-Driven Software Development Life Cycle）的目标是从需求到发布的周期，提升端到端效能。依托 AI-Ready PRD、AI-Ready 仓库、SDD 研发流程、质量保障，以 AI 驱动各阶段工具与方法的协同升级，实现端到端交付效率提升。

    3.4.3 方案概设

    为什么会有概设阶段？PRD 是功能视角，后端是技术实现的系统架构视角，两者之间目前缺少：① 从功能视角转化为系统架构视角的领域知识；② 系统间交互的接口协议。

    概设（概设方案模板）作为承接环节，核心工作包含两部分：①从需求中提取本领域相关的功能清单；②补充系统间交互的接口协议。输入概设，结合仓库 Context、团队 Context（外挂知识）以及 Agent 对代码的 Deep Research，Spec Coding plan阶段生成完整的详设。

    随着需求 Spec 规范化程度的持续提升，以及需求 Spec → 前端 → 后端全链路系统架构知识库的不断完善，概设阶段将逐步淡出——具备对需求自动 Breakdown 与自动生成各领域详设的能力。

    3.4.4 AI-ready仓库

    AI-ready的仓库指AI对仓库的可理解性、可测性、可持续性。实践经验中，给AI提供仓库导航 AGENTS.md，索引指向业务context，包含核心实体、系统架构、业务流程等，可大幅提升AI生码率。

    5、演进方向

  • 成果持续沉淀。AI-SDLC实践中产生的探索成果会持续落到这个系统中，如AI-Ready PRD、AI-Ready仓库、各种质量保障工具等，持续提升效果。
  • 通过多模版支持不同场景、不同复杂度的需求。初期提供SDD流程（中等以上复杂度）和Claw流程（单仓一句话需求，Skills编排全流程）。

    • 更进一步，未来会实现研发流程柔性化，支研发根据自己团队的实际业务场景自定义流程，平台做好基建能力支撑。

  • 质量门禁的自动化及反馈回路的构建。AI生码、AI自动执行并不关键，关键在于可控、有稳定的质量输出。每个节点的输入输出要有清晰的规范，并构建配套的质量门禁检测产物的质量，将检测结果反馈给AI，让AI在Loop中自行完善。
  • 数据反向驱动流程优化。每跑一个任务，系统都在积累数据：哪个节点最容易卡住、AI 生成内容被打回的比例、不同类型任务的平均完成时长、哪些 review 意见反复出现。这些数据沉淀下来，就能反过来优化流程本身。

    • 6、One More Thing——人与AI角色的演变

    **阶段****人的角色****AI 的角色**
    现在执行者 + 审核者辅助生成
    近期主要审核者主要执行者
    未来流程设计师全流程执行者

    这个演变的终态不是"零人工"，而是人的工作重心从写代码转移到设计更好的研发流程。就像现代工厂里，一线工人越来越少，但工程师在设计更智能的机器和更高效的产线。

    团队的核心竞争力，最终会体现在：你设计的研发流程有多好，而不是你的工程师有多能写代码。
