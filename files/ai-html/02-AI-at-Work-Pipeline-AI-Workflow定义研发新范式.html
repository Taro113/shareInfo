AI at Work：Pipeline AI Workflow 定义研发新范式

一条命令，十个阶段，从"我有个需求"到"提测"全程自动化

一、Pipeline AI Workflow 是什么？

Pipeline AI Workflow 是一个研发全生命周期工作流自动化框架，运行在 CatClaw/CatDesk/CatPaw…（美团 AI Agent 平台）上。

它的核心理念是：把研发交付流程的每个阶段都变成可执行的自动化节点，通过声明式 DAG 串联成一条端到端的流水线。从需求分析开始，到最后交付报告，十个阶段自动衔接，每个阶段完成后自动写入学城文档，无需人工等待确认直接进入下一阶段。

二、涉及的 Skills 与 MCP Tools 全景

Pipeline AI Workflow 是一个工作流控制器，它将以下 sub-agent 和 MCP Tools 串联调度。https://km.sankuai.com/collabpage/2752188868

核心 sub-agent（来自 pipeline-workflow）

阶段sub-agent 名称作用
阶段一`requirements-analyst`将模糊需求转化为结构化 PRD，主动识别歧义，发起澄清问题
阶段一`evaluate-requirements`评估技术可行性、工作量（L/M/H）、爆炸半径、风险点
阶段二`pipeline-services-analyst`三轮评分判定需求涉及哪些微服务仓库（Owner/Contributor）
阶段二`technology-plan-reviewer`对技术方案进行架构评审，识别设计风险
阶段四`using-git-worktrees`基于 feature 分支创建隔离 Git Worktree，防止分支污染
阶段四`writing-plans`生成 TDD 驱动的 bite-sized 实施计划，每步含完整代码和测试命令
阶段四`subagent-driven-development`每个任务派独立 Sub-agent，双轮 Review（Spec合规 + 代码质量）
阶段五`code-commit-assistant`分析 diff 自动生成符合 Angular 规范的 Commit Message
阶段五`pipeline-pr-creator`自动创建 PR，关联 MEP 工作项
阶段五`pr-code-reviewer`基于需求/技术方案提炼 Review 依据矩阵，行级评论，自动 Approve
阶段六`test-case-generator`生成正常/边界/异常三类测试用例，写入学城

外部 Skills（独立安装）

阶段Skill 名称作用
阶段三、七`ee-ones`创建 MEP 工作项、管理分支、关联工作项、创建提测单
全程`citadel`读写学城文档，每个阶段产出自动存档
阶段七`ee-pipeline`触发执行流水线，回收流水线执行结果和日志

工具用途

    七、设计理念

  • 测试驱动开发 — TDD 贯穿全流程，增量覆盖率 ≥ 60% 为硬门控，五层防线确保质量
  • 系统化而非随意 — 声明式 DAG 驱动流程，非 ad-hoc 脚本
  • 多层防线 — 覆盖率五层检查，评审门控 fail-closed，评审状态机保证收敛
  • 非阻塞通知 — 阶段进度实时推送大象群，不阻塞主流程
  • 优雅降级 — 工具缺失时警告而非崩溃，保持流程可用
  • 幂等与断点续跑 — 任何阶段可重复执行，失败后可断点恢复

    • 写在最后

    Pipeline AI Workflow不是要替代研发——它是要让研发回归真正有价值的工作。

    重复性的流程（需求对齐 → 方案沉淀 → 编码实现 → Review 意见 → 测试用例）是可以系统化的，Pipeline AI Workflow 把这些做掉了。

    剩下的——技术判断、架构权衡、产品洞察——才是研发不可替代的价值所在。
