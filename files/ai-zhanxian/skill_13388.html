简介

imd 设计稿数据获取与分析工具集（D2C）。当用户提供 imd.sankuai.com 设计稿链接，或需要从设计稿中提取结构/样式/CSS 信息时触发。

关键词：设计稿、imd、mastergo、d2c、图层、节点、CSS、样式。

编码铁律（必须遵守）

  • 先规划再编码：拿到 JSON 后先 fetch_skeleton + 看截图 → 划分模块 → 批量导出切图。禁止跳过规划直接写代码
  • 逐模块实现：每个模块走 inspect_node → 编码 → 截图对比设计稿 → 修复循环。禁止一次性实现整个页面
  • 每个模块必须 Diff：写完一个模块就截图对比，发现偏差立刻修复。禁止跳过 Diff 进入下一个模块
  • 数据驱动：所有 CSS 值必须来自 inspect_node 输出，禁止凭记忆猜测任何数值

Setup（每次会话首次使用时执行）

Local 模式：

# 检查状态文件与 daemon
cat .d2c/.setup-state.json 2>/dev/null
curl -s http://127.0.0.1:19826/ping

# 启动 daemon
cd ${SKILL_DIR}/daemon && npm install --silent 2>&1 && cd -
mkdir -p .d2c && node ${SKILL_DIR}/daemon/server.mjs --out-dir "$PWD/.d2c" >> .d2c/daemon.log 2>&1 &
sleep 2 && curl -s http://127.0.0.1:19826/ping

# 检查扩展连接
curl -s http://127.0.0.1:19826/api/status  # extensionConnected: true

Remote 模式：询问用户获取设计稿信息（插件复制的 JSON），运行：

python ${SKILL_DIR}/scripts/download_d2c.py <documentId> --frame-id "<layerId>" --outdir "$PWD/.d2c"

工作流

Phase 1（编码前必做）：看骨架 + 截图 → 划分模块边界 → 确认切图需求并批量导出 → 识别复用结构

Phase 2（逐模块循环）：Skeleton 查看结构 → Inspect 提取样式 → Code 按数据编码 → Diff 截图对比设计稿 → Fix 修复差异

步骤操作工具
Skeleton查看模块子树结构fetch_skeleton --root-id <moduleId>
Inspect提取样式数据inspect_node <id> / extract_leaves <id>
Code按 JSON 数据编码见编码规则
Diff截图对比设计稿截图当前实现，与 .png 对比
Fix修复视觉差异定位偏差 → 重新 inspect → 修正代码

编码规则

数据驱动：每个 CSS 值必须来自 inspect_node / extract_leaves 输出，禁止凭记忆猜测。同构模块的第一个走完整 inspect；其余只提取差异字段（textContent、图片路径）。

文本逐字保留：textContent 必须原样使用，禁止改写、缩略、替换分隔符或标点。Unicode 字符（中文引号、竖线、特殊空格）不得替换为 ASCII 近似字符。

元素数量对齐：编码前先数 JSON 中目标模块的直接 children 数量，实现后的 DOM 元素数必须与 JSON 一一对应，不增不减。

布局方向校验：父节点 style.display === "flex" 时，无 flexDirection 或值为 "row" → 子元素横排；flexDirection: "column" → 子元素竖排。禁止将横排设计实现为竖排。

核心规范

  • 先规划再编码：Phase 1 组件规划完成后才开始写代码
  • 逐模块 + Diff 闭环：每个模块走 inspect → code → diff → fix 循环，不跳过 diff
  • 一次 HTTP 调用：序列化、切图都是单次 curl 调用，daemon 自动处理
  • 数据驱动：样式数值来自工具输出，不凭记忆猜测
  • 避免将大型 JSON（>500 行）全量 Read 到上下文——使用 Python 脚本按需提取
  • _exportSrc 与 children 共存时，默认同一模块，避免重复实现
