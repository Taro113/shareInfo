简介

面向需求交付与开发执行的端到端编排 skill。用于处理需求澄清、组件前端技术方案、活动配置与后端服务方案、分支准备（可选 Fedo 或按需求从 master 创建分支）、编码、自测、部署测试环境、自动化测试、提 PR 与智能 CR、自动检查可合并状态并合并、上线发布等完整流程。

共 8 个阶段：需求澄清 → 技术方案与协同契约 → 分支准备 → 编码 → 部署测试环境 → 自动化测试 → 提 PR 与智能 CR → 上线发布。

支持从阶段一完整开始，也支持从部署测试环境、自动化测试、提 PR、上线等中间阶段介入，并支持会话断点续接。支持用户显式要求时对阶段一/需求澄清阶段做复盘。

流程总览

阶段一：需求澄清 — 需求预检 + 业务组件定位 + 分轮澄清 + 生成澄清版 PRD；可选：用户显式要求时生成阶段一复盘。

阶段二：技术方案与协同契约 — 基于澄清文档 + 代码分析，按 owner 生成 FE / BE 方案，并对齐接口与配置契约。

阶段三：分支准备 — 询问用户走 Fedo 流程，还是根据需求从 master 创建开发分支。阶段三完成后，状态进入「开发中」。

阶段四：编码 — 切换分支 + 按技术方案逐项编码 + 自测；编码完成后询问继续部署测试环境，还是创建 PR 到 master。

阶段五：部署测试环境 — Talos 部署 + 监听流水线。

阶段六：自动化测试 — 读取需求条目 + 技术方案 + 分析 diff + 生成测试用例 + 浏览器自动化执行 + 生成报告 + 归档学城。

阶段七：提 PR 与智能 CR — 创建/更新 PR + 调用 smart-cr 审查 + 轮询 PR 可合并状态，3 分钟内可合并则自动 merge；超时则停留当前阶段，回传 PR 链接给用户检查。

阶段八：上线发布 — 调用 talos-project-publish 执行正式发布。阶段八成功后，状态变为「已完成」。

触发条件

用户明确提到 hotel-sdd；或用户提供需求/任务/仓库/分支/PR/部署环境/测试地址等任一交付上下文；或用户希望按流程推进需求，例如：

  • "帮我开发"、"帮我改动"、"做个需求"、"提交代码"
  • "部署测试环境"、"跑自动化测试"、"提 PR"、"帮我 CR"
  • "上线发布"、"新需求"、"帮我做需求"
  • 用户显式要求复盘阶段一或需求澄清阶段

核心原则

  • 每阶段结束必须等待用户确认，不得自动跳入下一阶段
  • 技术方案（必要时包含协同契约）必须先于代码，未经用户确认的技术方案不得开始写代码
  • 状态驱动：阶段间信息通过状态对象传递，禁止依赖对话历史
  • 状态持久化：每阶段完成后将状态写入 Skill 运行目录，不写入业务仓库
  • 状态写入失败必须阻断推进：不得静默进入下一阶段

开发中改动级别判断

需要技术方案（回到阶段二）：涉及新增/修改业务逻辑的功能开发、需要对接新接口的改动、模块级别的重构。

不需要技术方案（直接改代码）：文案/颜色/间距等 UI 微调、原因明确的 Bug 修复、配置变更、依赖升级、纯样式调整。

无法判断时，问用户一句："这个改动需要走技术方案流程吗，还是我直接改？"

会话续接

Skill 触发时，先读取 config/hotel.yaml 获取团队配置，然后检查是否存在未完成的流程：

  • 命中多个 _phase ≠ done 的状态文件 → 展示候选列表并让用户选择
  • 仅命中一个且 _phase ≠ done → 询问用户继续还是重新开始
  • 不存在 → 正常从阶段一开始

外部依赖

主要依赖：talos-project-publish（阶段五/八）、hotel-marketing-backend / marketing-backend（阶段五 BE）、smart-cr（阶段七）、explore-design-tree-remote（阶段四 FE 设计稿还原）、max-preflight（阶段四样式规范预检）、chrome-devtools-mcp（阶段四联调/阶段六测试）。

按阶段检查依赖，不在流程一开始全量安装。缺失依赖时先告知用户，不得未经确认自动安装。
